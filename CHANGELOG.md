# Changelog

## Unreleased

- `formal/`: the Lean 4 project of the proofs about `hayai-consensus-core`, with the committed translation of the crate (`formal/README.md`). `hayai-consensus-core`: the modules `spec`, `rules`, `limits`, `subsidy`, `header` and `difficulty` are `chain_spec`, `rule_sets`, `block_limits`, `subsidy_schedule`, `header_rules` and `difficulty_rules`; `CoreSpec::funding_streams`, `lockbox_disbursements` and `founders_scripts` are `Vec`s; `rules_at` returns a `RuleSet` by value; `RuleSet::of` is not `const`; `check_contextual` and `expected_bits` take `ParentChain` by value; `CoinbaseTerms::check` takes `&[CoinbaseOutput]`. `hayai-consensus`: `rules::rules_at` is unchanged; `coinbase::CoinbaseOutput` is re-exported; `check_contextual`, `check_header` and `expected_bits` take `&ParentChain` as before.
- `hayai-consensus-core`: new crate with the consensus rules as pure functions (`CoreSpec`, `Upgrade`, `rules`, `subsidy`, `funding`, `lockbox`, `founders`, `nsm`, `difficulty`, `header`, `coinbase_value`). `hayai-consensus` wraps it: `coinbase::terms_at` and `coinbase::terms_after` replace `CoinbaseTerms::at` and `CoinbaseTerms::after`; `CoinbaseTerms::miner_subsidy` is a field; `CoinbaseTerms::miner_fees`, `nsm::miner_fee_share` and `nsm::reissuance_bonus` return a `Result`; `funding::funding_streams` returns a `Result` and gives scripts (`FundingStream::script`), with `address_of` for the address; `founders::FoundersReward` and `lockbox::disbursements` give scripts; `RequiredOutput::script` is a `[u8; 23]`; `branch_id(upgrade)` replaces `Upgrade::branch_id()`, and `Upgrade::of_branch` takes a `u32`; new `Network::core()`, `ChainSpecError::Rule`, `ConsensusError::{MoneyOverflow, Overflow, DivisionByZero, UncheckedSpec}`.
- `hayai-mempool`: new crate with `PreparedStore`, `InsertError`, `EntryFees`, `MempoolPolicy`, `PolicyReject` and the ZIP 401 and policy constants, which were in `hayai-prepared`, and `Mempool` and `Reject`, which were in `hayaid`. Use `hayai_mempool::PreparedStore` instead of `hayai_prepared::PreparedStore` (the same for each item). `hayai-prepared`: new trait `PreparedLookup`; this version removes `PreparedTx::candidate` (use `Candidate::from_raw`). `hayai-validate`: the validation functions take any `PreparedLookup`; this version removes the re-export `hayai_validate::PreparedStore`. `hayai-fixtures`: new module `regtest` (`spend_tx`, `shielding_tx`, `Spend`).
- `hayai-consensus`: a crate defines a chain as data. New types `ChainSpec` and `CheckedSpec`, and `Network::spec()`. `Network::Custom(CheckedSpec)` replaces `Network::ConfiguredRegtest(&'static RegtestConfig)`: get it from `ChainSpec::network()` or `RegtestConfig::network()`. New method `Network::network_type()`. `RegtestConfigError` is now `ChainSpecError`. `NetworkParams` has no `network` field. `funding::StreamSet` and `funding::Stream` are public. `hayai-wire`: `PowParams` implements `Hash`.
- `hayaid`: the error of a `[regtest]` activation height out of order has a new text: "the activation height H of U is below the height of an earlier upgrade, or it is a Regtest height that is not above 1".
- `hayai-fixtures`: new crate with the fixture generator. The generator was `hayai_bench::fixtures`. Use `hayai_fixtures::transparent_block` instead of `hayai_bench::fixtures::transparent_block` (the same for each item). `hayai-fuzz` no longer depends on `hayai-bench`.
- Race deployment (`scripts/race_deploy.sh`, `docker/race`, `deploy/terraform/aws-race`): the iptables rules of the node machines keep loopback open, so `status` and `collect` read the metrics again; Grafana listens on `127.0.0.1` by default (SSH tunnel; the Terraform path keeps `0.0.0.0` behind its security group); the directory of the Grafana password is private (the file stays readable for the Grafana container); `race_deploy.sh` passes `RACE_GRAFANA_ADDR` to C; `start` checks `sudo` before it starts anything; `collect` records the start times of the Terraform path; the race units are enabled (with an `[Install]` section), so a reboot before the start time does not lose the start. The runbook lists the prerequisites, the checkpoint path of hayaid and 3 more fairness rules.
- `hayai-prepared`: a v5 or v6 transparent input signed with `SIGHASH_SINGLE` (or `SIGHASH_SINGLE | ANYONECANPAY`) and no output at its index fails its signature check (ZIP 244 S.2a, as zcashd, Zebra and Zakura). Before, hayai hashed an empty output list and accepted such a signature.
- `hayaid`: a peer whose protocol version is below the version of the upgrade of the tip is refused at the handshake and disconnected when the upgrade activates (ZIP 201, ZIP 204, as Zakura). Before, the minimum stayed at 170,150.
- `hayai-net`: a `ping` before the end of the handshake gets no `pong` (ZIP 204). Before NU5 the relay does not fetch a `MSG_WTX` announcement (ZIP 239).
- `hayai-wire`: new method `TxLookup::for_each_relay_id`. The answer to `mempool` leaves out a transaction that expires within 3 blocks of the next block (ZIP 204). `PreparedStore::relay_ids` is removed.
- Docs: `docs/consensus.md` gives each consensus rule of the ZIPs and of the protocol specification in one row, with a link to the line of the code that enforces it and to its test, or the reason why hayai does not implement it, and the open points. It replaces `docs/consensus-rules.md`. The code marks each rule with `// ZIP <n>: ...` or `// Spec §<section>: ...`.

The index holds transactions by id, transparent addresses and note commitment subtrees in `cache_dir/wallet-index`. The node writes it for each committed block and undoes it on a reorg. The index stays consistent after a crash. Metrics `hayai_wallet_index_*`. `docs/hayaid.md`, Wallet index.
- `hayaid`, `hayai-rpc`: methods `getrawtransaction`, `gettxout`, `getaddressbalance`, `getaddresstxids`, `getaddressutxos` and `z_getsubtreesbyindex` with the request and answer shapes of Zakura. New types `IndexError`, `TransparentAddress`, `AddressUtxo`, `TxOutInfo`, `SubtreePool`, `SubtreeRow`.

- `hayaid`: the block download no longer gives a stall to a Zebra or Zakura peer when a row of large blocks follows small blocks. Such a peer answers at most 1 MB of 1 `getdata` message. The requests of the message after its answered blocks become free again when the peer answers a later message. On Testnet the old rule disconnected each peer that served blocks near height 4,308,000 and refused it for 10 min and more.
- `hayaid`: a header chain without bodies comes back into the fork choice when a peer that connected after the exclusion sends a header of it. It no longer comes back at each `headers` message of a peer that did not send the block (before, the node repeated the exclusion about each second). The node logs the warning `no peer sends the block` 1 time for a block, then at most 1 time for each wait. The warning has the fields `peers` and `wait_ms`.
- `hayai-sync`: the bound of the side headers does not count the headers that are out of the fork choice (`HeaderChain::mark_unavailable`). With more than 65,536 such headers the chain removed the newest headers of the best chain.
- `hayai-sync`, `hayaid`: `headers.log` has 1 header record for each header. A header that the chain removed and accepted again gets a mark (record kind 2, `Record::Again`, `HeaderLog::append_again`) and no second header record. At a start, the node accepts a log of an earlier version with a second header record. It uses the first record and writes 1 warning with the count (`HeaderChain::duplicate_records`). This version removes `OpenError::DuplicateHeader`. A version before this one does not read a log with a mark.
- `hayaid`: a peer can have no new header and send no answer to `getheaders` (Zakura, Zebra, zcashd). The node no longer disconnects such a peer with a stall penalty after `header_timeout_ms`. The stall rule of the header sync applies only to a peer with evidence of more headers than the node has. When no header sync is in progress, the node sends `getheaders` to 1 peer at a time. The delay doubles from `[sync] header_poll_ms` (30 s) to `header_poll_max_ms` (8 min) and starts again at each new block. `SyncConfig::{header_poll_ms, header_poll_max_ms}`, `sync::{HEADER_POLL_MS, HEADER_POLL_MAX_MS}`.
